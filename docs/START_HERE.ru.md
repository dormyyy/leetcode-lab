## Как писать C++ без чтения входа

На LeetCode реализуй предложенный метод класса `Solution`. `cin` и `main` там не нужны: платформа передаёт аргументы и проверяет возвращаемое значение.

Например, `[2,4,3]` у `Add Two Numbers` — представление связного списка, а не требование самостоятельно читать строку. Локальная обвязка создаёт `ListNode`, передаёт указатель методу и выводит результат как массив. Деревья строятся из обхода по уровням с `null` для отсутствующих узлов.

В `solution.cpp` уже есть настоящая сигнатура из LeetCode. Замени `throw std::logic_error(...)` своим алгоритмом. Содержимое этого файла можно вставлять в редактор LeetCode. `main.cpp`, `types.hpp`, локальные определения узлов и сгенерированные вызовы отправлять не нужно.

Запуск из терминала:

```powershell
python tools/leetcode.py run add-two-numbers
```

Команда использует `g++`/`clang++` из PATH или уже установленный MinGW из CLion в `E:\Progs`. Глобальные настройки PATH не меняются.

В CLion открой корень репозитория, выбери toolchain, перезагрузи CMake и запусти `problem_0002-add-two-numbers`. Python используется CMake только для генерации локальных вызовов. Другие задачи не конфликтуют между собой.

## Свои тесты: данные вместо парсинга

Файл `cases.json` содержит список случаев; в `inputs` перечислены аргументы метода в том же порядке, что на LeetCode:

```json
[
  {
    "inputs": [[2, 4, 3], [5, 6, 4]],
    "expected": [7, 0, 8]
  },
  {
    "inputs": [[0], [0]],
    "expected": [0]
  }
]
```

Скачанные примеры содержат только `inputs`, поэтому первоначально запуск показывает результат без утверждения, что он правильный. Добавь `expected`, если хочешь автоматическую проверку. Пустой список и пустое дерево обозначаются `[]`.

При запуске команды `run` или сборке CMake файл `cases.generated.hpp` создаётся заново. Его не нужно редактировать и коммитить. `main.cpp` и твой код при этом не перезаписываются.

Поддерживаются числа, bool, строки, символы, массивы, матрицы, `ListNode`, `TreeNode` и обычные задачи с последовательностями вызовов классов вроде `MinStack`. Для design-задач в `inputs` находятся два массива: имена операций и их аргументы. Например:

```json
{
  "inputs": [["MinStack", "push", "top"], [[], [4], []]],
  "expected": [null, null, 4]
}
```

Задачи со специальным judge, интерактивным API или неподдерживаемыми типами получают `runner: "manual"`: допиши вызовы в `main.cpp`. Генератор не пытается угадать их поведение. Исходные сигнатуры сохраняются.

Для массивов и строк `expected` проверяется с точным порядком элементов; LeetCode иногда принимает несколько правильных ответов. В таких задачах убери `expected` или добавь собственную проверку в `main.cpp`. Для одиночного числа с плавающей точкой допускается погрешность `1e-9`; вложенные массивы чисел сравниваются точно. Локальные случаи не заменяют полный judge LeetCode.

Локальные builders создают узлы динамически для короткого тестового запуска и не удаляют узлы результата; эта обвязка не является проверкой утечек памяти.

## Что именно синхронизируется

В `leetcode.json` указан публичный username. Пароль, cookies и токены LeetCode не нужны. Используется публичный GraphQL, который читает сайт; это не официальный стабильный SDK, поэтому схема или доступность могут меняться.

```powershell
python tools/leetcode.py sync
```

В README есть две независимые цифры:

- **LeetCode account:** все решённые задачи профиля, включая старые Python-решения.
- **Repository journal:** задачи с сохранёнными файлами здесь и их статусы.

Последние публичные Accepted позволяют отметить соответствующую локальную задачу `solved`. Пустой starter автоматически решённым не считается: сначала сохрани свой код. Публичный список ограничен 20 записями и сейчас не содержит старых восьми решений, поэтому их имена и исходники из него получить нельзя. Сам счётчик этих решений доступен.

Если Accepted старый или не попал в публичный список, отметь его явно:

```powershell
python tools/leetcode.py done add-two-numbers
```

Этот статус означает, что задача принята LeetCode; он не доказывает, что текущий локальный файл идентичен отправленному варианту. Повторная отметка сохраняет первоначальную дату.

GitHub Actions обновляет данные на соответствующих push и по расписанию раз в шесть часов. Планировщик GitHub может задержать запуск. При ошибке запроса последняя успешная статистика сохраняется. Если данные не изменились, новый коммит не создаётся.

## Опубликовать локальный код

Перед началом работы можно забрать обновления счётчика с GitHub через `git pull`. После решения:

```powershell
python tools/leetcode.py sync
git status
git add problems README.md progress/leetcode.json
git commit -m "Solve 0002: Add Two Numbers"
git push
```

Если удалённая ветка обновилась за время работы и push отклонён, сначала выполни `git pull --rebase`, затем `git push`. Git сохраняет локальные коммиты; при конфликте остановится для его разрешения.
